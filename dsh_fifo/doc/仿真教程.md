# 仿真教程 — 从零开始

本教程假设你刚拿到这个工程，什么都不知道。按顺序做，每步都有"验证点"，
做完一步确认一步，出错时就知道卡在哪里。

---

## 0. 先理解：仿真在做什么

| 概念 | 在本工程里是谁 | 作用 |
|---|---|---|
| **设计（DUT）** | `rtl/` 下 9 个 `.v` 文件 | 被测试的电路：两个异步 FIFO + 监控模块 |
| **测试平台（TB）** | `tb/` 下 4 个 `.sv` 文件 | 给 DUT 施加激励、检查输出是否正确 |
| **仿真器** | ModelSim 10.3c | 真正执行 HDL 的程序 |
| **激励** | TB 里的 `wr_a()`/`rd_a()` 等任务 | 模拟上游写数据、下游读数据 |
| **检查点** | TB 里的 `ck()` 语句 | 断言"此刻某信号应该等于某值" |

**仿真三步**（ModelSim 的两个命令）：

```text
① 编译  vlog  →  把 .v/.sv 源码翻译成仿真库里的"设计单元"，产物放 work 库
② 加载  vsim  →  把 work 库里的 tb_top 装配进仿真内核
③ 运行  run   →  推进仿真时间，让激励跑起来，检查点逐条生效
```

TB 跑完会打印 `RESULT: *** PASS ***` 或 `*** FAIL ***`，失败会列出每条 `[FAIL]`。

## 1. 工程文件地图

```text
C:\work\czh\dsh_fifo\
├── rtl\                     ← 设计源码（Verilog，被测对象）
│   ├── common\              同步器、格雷码编解码、复位同步
│   ├── fifo\                async_fifo（FIFO 核）、fifo_a、fifo_b
│   └── top\                 monitor（监控）、dual_async_fifo_top（顶层）
├── tb\                      ← 测试平台源码（SystemVerilog，UTF-8 编码）
│   ├── tb_top.sv            顶层：时钟、驱动器、参考模型、9 个用例
│   └── env\                 tb_harness（接线）、tb_pkg（工具）、tb_coverage（覆盖）
├── build\gbk_2stage\        ← 编译用的 GBK 副本（脚本自动生成，14 个文件）
├── sim\msim_2stage\         ← 2 级同步器的仿真库（work 库 + 编译产物）
├── sim\msim_3stage\         ← 3 级同步器的仿真库
├── sim\logs\                ← 每次运行的日志
├── sim\waves\               ← 波形文件（VCD）
├── scripts\                 ← 自动化脚本
└── doc\                     ← 课程设计报告
```

先按 [工程 README](../README.md) 配置 ModelSim。以下命令假设工程位于 `C:\work\czh\dsh_fifo`，请换成你的实际路径。

| 坑 | 原因 | 本工程的处理 |
|---|---|---|
| 源文件不能直接用 `tb\` 里的 | ModelSim 在中文 Windows 上按 **ANSI/GBK** 读文件，而 `tb\` 是 **UTF-8**，直接编译中文会乱码甚至报语法错 | 脚本先把 UTF-8 转成 GBK，放进 `build\gbk_2stage\`，**编译时用这份** |
| 工程路径不能含中文 | ModelSim 内部 sqlite 无法在中文路径建库，会报 `sqlite3_open ... unable to open database file` | 工程放在纯 ASCII 的 `C:\work\czh\dsh_fifo` |

## 2. 方式 A：一条命令跑完（先建立信心）

打开 **CMD**（不是 PowerShell 也行），执行：

```bat
cd /d C:\work\czh\dsh_fifo
scripts\run_sim.cmd tc1 1 2 verify
```

### 这条命令的 4 个参数

```text
scripts\run_sim.cmd  <用例>  <随机种子>  <同步级数>  <模式>
                        tc1        1           2       verify
```

| 参数 | 可选值 | 含义 |
|---|---|---|
| 用例 | `tc1`~`tc9`、`tcA` | `tcA` = 依次跑全部 9 个 |
| 随机种子 | 任意正整数 | 改变随机激励；同一 seed 结果可复现 |
| 同步级数 | `2` 或 `3` | 2 级 / 3 级同步器配置 |
| 模式 | `verify` / `noverify` / `dump` | 重新编译 / 跳过编译 / 额外生成波形 |

### ✅ 验证点：你应该看到

```text
[run_sim] root = C:\work\czh\dsh_fifo
[run_sim] converting UTF-8 sources to GBK in build\gbk_2stage ...   ← 编码转换
[run_sim] converted 13 files
[run_sim] compiling (SYNC_STAGES=2) ...                            ← ① 编译
[run_sim] compile OK
[run_sim] running TEST=tc1 SEED=1 STAGES=2 ...                     ← ②③ 加载+运行

[run_sim] TEST=tc1  SEED=1  STAGES=2
[run_sim] failed checks    : 0          ← 1065 个检查点，0 个失败
[run_sim] coverage bins    : 25/29      ← 命中的功能覆盖点
[run_sim] functional cover.: 86.2 percent
[run_sim] log -> sim\logs\run_tc1_seed1_2stage.log
[run_sim] RESULT: *** PASS ***          ← 总体结论
```

看到 `*** PASS ***` 就成功了。**这一步成功后，说明设计、TB、工具链全部正常**，
后面只是怎么"看"的问题。

### 其它常用命令

```bat
scripts\run_sim.cmd tc4 7 2 verify     rem 换用例 tc4、换种子 7
scripts\run_sim.cmd tc1 1 3 verify     rem 3 级同步器
scripts\run_sim.cmd tc1 1 2 dump       rem 同时导出 VCD 波形
scripts\regression.cmd                 rem 全量回归：9 用例 × 2 种级数 = 18 次
python scripts\mutation_test.py        rem 变异测试：验证"测试本身有效"
```

#### 第 1 步：启动 ModelSim

双击 ModelSim 安装目录中的 `vsim.exe`（不带任何参数）。

**✅ 验证点**：出现 ModelSim 主窗口，下方有 **Transcript** 输入区，
提示符是 `ModelSim>`。

#### 第 2 步：切到仿真库目录

```tcl

```

应该回显：

> `vsim work.tb_top` 必然失败。

**这个目录里已经有编译好的库**（`work` 子目录），所以可以直接跳到第 4 步。

**✅ 验证点**：最后一行显示 `Errors: 0, Warnings: 0`。

#### 第 6 步：看波形

**方式一（推荐，最省事）**：在 Transcript 里敲

```tcl
add wave -r /tb_top/h/*
```

左侧会出现 Wave 窗口，列出所有信号。

**方式二（只看关键信号）**：

```tcl
add wave /tb_top/h/wr_clk_a
add wave /tb_top/h/rd_clk_a
add wave /tb_top/h/u_dut/u_fifo_a/u_fifo/wr_bin
add wave /tb_top/h/u_dut/u_fifo_a/u_fifo/rd_bin
add wave /tb_top/h/u_dut/u_fifo_a/u_fifo/wr_full
add wave /tb_top/h/u_dut/u_fifo_a/u_fifo/rd_empty
```

**注意**：如果波形窗口里信号显示 `<no data>` 或丢失内部信号，说明加载时没加
`-voptargs=+acc`。重新加载：

```tcl
vsim -voptargs=+acc work.tb_top +TEST=tc1 +SEED=1 +STAGES=2
run -all
```

**✅ 建议观察的 4 个现象**（答辩时按这个讲）：

1. **时钟比**：`wr_clk_a` 周期 10 ns，`rd_clk_a` 周期 6 ns（5:3）
2. **写满和握手**：`wr_full_a` 拉高时 `wr_ready_a` 立刻为 0，`wr_bin` 停止增长
3. **读空和有效**：`rd_empty_a` 拉高时 `rd_valid_a` 为 0
4. **格雷码跨域**：`wr_bin`/`rd_bin` 是二进制指针，同步到对方域时经过格雷码转换，
   每一步只有 1 bit 变化（可以在 `u_sync_wr_ptr` 里看）

## 4. 怎么判断"验证通过了"

分三个层次看，缺一不可：

| 层次 | 看什么 | 通过标准 |
|---|---|---|
| **① 断言** | `failed checks` / `[FAIL]` 列表 | 必须为 **0** |
| **② 数据完整性** | `check_data()` 的比对结果 | 无 `[FAIL]`（说明无丢失/重复/乱序） |
| **③ 覆盖率** | `FUNCTIONAL COVERAGE = xx%` | 单用例 48%~90%；全部用例合并需 **100%** |

**⚠️ 只看"没报错"是不够的**。必须再跑一次变异测试，确认断言有判别力：

```bat
python scripts\mutation_test.py
```

预期：

```text
M1_off_by_one_full: CAUGHT (6 failed checks)
M2_wrong_threshold: CAUGHT (3 failed checks)
M3_no_hysteresis:   CAUGHT (2 failed checks)
结论: 3/3 个变异被捕获
```

它故意往 RTL 注入 3 个 bug，看测试能不能抓到。**3/3 全部捕获**说明测试有效。
脚本会自动恢复 RTL 原文件（用 `.mutbak` 备份，`finally` 里还原）。

## 5. 常见问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击脚本一闪而过 | 路径没切对 | 先 `cd /d C:\work\czh\dsh_fifo` 再执行 |
| 弹窗后 ModelSim 退出 | 库路径不对（`pwd` 不是 `sim\msim_2stage`） | 先 `File → Change Directory` 切对，再 `pwd` 确认 |
| `Cannot find design unit work.tb_top` | 同上，或库没编译 | `vdir work` 看有没有 `tb_top`；没有就重新编译 |
| 中文变乱码 / 语法错 | 编译了 `tb\` 里的 UTF-8 原件 | 改用 `build\gbk_2stage\` 的 GBK 副本 |
| `sqlite3_open ... unable to open database file` | 路径含中文 | 检出到纯 ASCII 路径 |
| 波形里信号是 `<no data>` | 没加 `-voptargs=+acc` | 重新 `vsim -voptargs=+acc ...` |
| `run -all` 很久不动 | 某个用例本来就慢（tc2 约 90 µs） | 耐心等，或先跑 `tc1` |
| 想中断仿真 | — | Transcript 敲 `stop` 或按工具栏 Break |
| 想退出 | — | `quit -f` |

## 6. 换用例、换配置

### 6.1 脚本方式

```bat
scripts\run_sim.cmd tc1 1 2          rem tc1, 种子1, 2级
scripts\run_sim.cmd tc4 7 2          rem tc4, 种子7, 2级

```

### 6.2 GUI 方式

换用例只需改 `vsim` 命令行里的 plusargs：

```tcl
vsim work.tb_top +TEST=tc4 +SEED=7 +STAGES=2
run -all
```

全部 10 个 plusargs：

| 参数 | 作用 | 默认 |
|---|---|---|
| `+TEST=` | 用例 `tc1`~`tc9` / `tcA`（全部） | tcA |
| `+SEED=` | 随机种子 | 1 |
| `+STAGES=` | 同步器级数 2/3 | 2 |
| `+DUMP` | 生成 VCD | 关 |
| `+PA_PS` `+QCA_PS` | A 通道写/读周期（ps） | 10000 / 6000 |
| `+PB_PS` `+QCB_PS` | B 通道写/读周期（ps） | 14000 / 4000 |
| `+MON_PS` | 监控时钟周期 | 5000 |
| `+PHA_PS` `+PHB_PS` | 读时钟初始相位 | 0 |

### 6.3 9 个用例分别在验证什么

| 用例 | 对应题目要求 | 验证内容 |
|---|---|---|
| `tc1` | 6.1 | 随机数据写满 256 → 查满标志/计数；读空 → 查空标志；数据逐项比对 |
| `tc2` | 6.2 | 5000+ 次混合读写，读写比动态变化（1:3~3:1），非整数时钟比 |
| `tc3` | 6.3 | 满后持续写 / 空后持续读，验证保护机制与溢出/下溢计数 |
| `tc4` | 6.4 | 阈值跳变点扫描：almost_full 在 224 置位、222 清除；almost_empty 在 32 置位、34 清除 |
| `tc5` | 6.5 | 随机拉低 `rd_ready` 制造背压，验证数据完整性与指针一致 |
| `tc6` | 6.6 | 双通道协同：A满B空 / A空B满 / 双 almost_full / 双背压 |
| `tc7` | 附加 | 复位期间零事务、复位释放后收敛 |
| `tc8` | 附加 | 全0/全1/交替模式，指针回卷 3 次 |
| `tc9` | 附加 | 时钟暂停 200 ns 后恢复，数据完整性 |

## 8. 一句话总结

```text
编译（vlog，用 GBK 副本）→ 加载（vsim，在正确目录）→ 运行（run -all）
→ 看 failed checks 是否 0 → 看覆盖率 → 跑变异测试确认断言有效
```

日常用 `scripts\run_sim.cmd`，演示用 `scripts\run_gui.cmd`，
两个脚本都替你处理了编码、路径、库这三件事。
