## 二、怎么拿到文件（实际路径与命令）

Sky130 的标准单元库在 GitHub 上，但**整个仓库含大量 GDS/LEF，体积过大**
（实测下到 68 MB 仍未完，且与另一路下载冲突导致文件损坏）。改用
**git sparse-checkout 只取需要的目录**：

```bash
git clone --depth 1 --filter=blob:none --sparse     https://github.com/google/skywater-pdk-libs-sky130_fd_sc_hd.git
cd sky130_fd_sc_hd
git sparse-checkout set cells/dfxtp        # 只拉 dfxtp 单元目录
```

这样只取到几 MB，目录结构（实测）：

```text
cells/dfxtp/
  sky130_fd_sc_hd__dfxtp_1.spice                       ← 22 管电路网表
  sky130_fd_sc_hd__dfxtp_1__tt_025C_1v80.lib.json      ← Liberty 数据（JSON）
  sky130_fd_sc_hd__dfxtp_1.cdl / .gds / .lef / .v
  sky130_fd_sc_hd__dfxtp_1__{ff,ss,tt}_*.lib.json      ← 其他工艺角
```

**注意**：该仓库里**没有 `.lib` 纯文本文件**，而是 `.lib.json`（Liberty 的 JSON 表示）。
若需要标准 `.lib`，要另外下载 `skywater-pdk` 主仓库的 `libraries/` 目录，
或用 Sky130 的 `libreliberty` 工具转换。

## 四、τ 的两条独立估算（并且它们不一致，这很重要）

### 方法 ①：从 SPICE 网表的器件尺寸算

网表给出 22 个晶体管，典型尺寸 `w=0.42 µm / l=0.15 µm`（n 与 p 各取中位）。
用 SKY130 工艺参数（tox≈4.1 nm → Cox≈8.39 fF/µm²、µn≈400 cm²/Vs、µp≈120 cm²/Vs、
Vov≈0.7 V）：

```text
gm_n = 660 µS,  gm_p = 198 µS,  gm_loop = 429 µS
C_node = 栅 1.06 fF + 漏结 1.51 fF = 3.63 fF
τ = C/(gm − gds) = 9.4 ps      [区间 4.7 ~ 18.8 ps]
```

### 方法 ②：从实测 clk-to-Q 反推

亚稳态时间常数与单级门延迟同量级，差一个环路增益：

```text
t_pd(单级) = clk2Q_min / 级数 = 0.2692 ns / 3.5 = 77 ps
τ = t_pd / ln(增益) = 77 ps / ln(4) = 55.5 ps
```

### 为什么要同时给两个

方法①**偏乐观**：它假设器件工作在强反型饱和区、未计速度饱和与体效应，
而亚稳态时管子实际处在线性区，有效 gm 更低，真实 τ 更大。
方法②更接近 130 nm 工艺公认的 **20~50 ps** 量级。

因此 MTBF 采用**保守（较大）的 τ**：`20 / 55.5 / 60 ps` 作为 min/typ/max，
三条都算一遍。这个处理方式本身也是结论：**τ 的估算有约 3 倍不确定度，
但它对 MTBF 的影响远小于 t_r 与频率**。

## 五、算出来的 MTBF

条件：`f_data = 100 MHz`、`t_skew = 0.05 ns`、`t_setup = 0.6207 ns`（最坏）、`T_w = 50 ps`。

| 目的时钟 | 级数 | t_r | τ=20 ps | τ=55.5 ps | τ=60 ps |
|---|---|---|---|---|---|
| 4 ns（250 MHz） | 2 | 3.329 ns | 10^59 年 | 10^12.5 年 | **10^10.5 年** |
| 4 ns（250 MHz） | 3 | 7.329 ns | 10^146 年 | 10^44 年 | 10^39 年 |
| 10 ns（100 MHz） | 2 | 9.329 ns | 10^189 年 | 10^60 年 | 10^54 年 |
| **1 ns（1 GHz）** | 2 | 0.329 ns | 2.83 s | 7.56e−5 s | 4.84e−5 s |
| **1 ns（1 GHz）** | 3 | 1.329 ns | 10^14.7 年 | 5080 s | 837 s |

**关键结论**：

1. 题目给定的 250 MHz 下，2 级最差也有 **10^10.5 年**，远超需求。
2. 1 GHz 下 2 级彻底失效（10⁻⁴ 秒），**3 级也只有 14 分钟~1.4 小时**——
   说明"加同步级数"不是提高频率上限的银弹，真正的限制是
   **setup 占时钟周期的比例**（0.6207 ns / 1 ns = 62%）。
3. 130 nm 工艺的可靠工作频率上限因此大约在 200 MHz 量级，与公开经验一致。

## 五点五、SPICE 表征已完成（真实结果）

在 ngspice 47 + SKY130 tt corner 上完成了真实的相位扫掠（`scripts/sky130_spice_sweep.py`）：

| 项目 | 数值 |
|---|---|
| 正常态 clk→Q | **168.13 ps** |
| **tau** | **53.75 ps** |
| T_w | ≈ 58 ps（亚稳态区 dt ∈ [−28, −58] ps 的边界） |
| 拟合 R^2 | 0.7144 |

**三条独立方法的一致性**：

| 方法 | tau |
|---|---|
| 行为模型 ODE | 9.01 ps（低估） |
| clk-to-Q 反推 | 55.5 ps |
| **SPICE 扫掠** | **53.75 ps** |

打通 SPICE 的 5 个关键点：① 补 8 个 `_slope` 参数；② **`.option scale=1.0u`**（缺它单位全错）；
③ 精简 corner（只留 dfxtp 用到的两个器件）；④ include 用绝对路径；⑤ 判据要排除
"data 晚于 clk 的正常不采样"。



`scripts/metastability_sweep.py` 实现了真正的"数据边沿相位扫掠 + 指数拟合"：

```text
对每个相位偏移 dt：算输出延迟 t(dt)
正常态 t = t_pd
亚稳态 t = t_pd + tau*ln(T_w/|dt|)
=> 对 ln|dt| 与 t 做线性拟合：斜率 = -tau，截距反解 T_w
```

**行为模型模式的结果**（16 个相位点，0.2~200 ps）：

| 项目 | 数值 |
|---|---|
| 进入亚稳态区的点数 | 15 |
| tau | **9.01 ps** |
| T_w | **451.97 ps** |
| 拟合 R^2 | **0.9962** |

`tau`=9.0 ps 与解析式 C/(gm−gds)=9.4 ps 一致（同一模型互验）；
`T_w`=452 ps 与 Liberty 的 setup 最坏值 0.62 ns 同量级，物理上合理。

**SPICE 模式**（`--spice <ngspice.exe>`）的代码已写好并自检通过：
它会为每个相位偏移生成一份 deck（含 `sky130_fd_pr` 的 TT 模型 include、
`.tran`、`.measure`），调用 ngspice 批量跑，再走同一套拟合。
本机当前没有 ngspice，因此该模式尚未产出 SKY130 的 SPICE 表征值。

**两个 tau 的区间**：行为模型 9.0 ps（偏乐观）↔ clk-to-Q 反推 55.5 ps（偏保守），
真实值应在此区间内。用这两个端点算出的 MTBF 分别列在下一节。

## 六、还缺 T_w（以及缺了会怎样）

`T_w` 是**亚稳态输入窗口宽度**，Liberty 文件不提供。它必须靠 SPICE 对该 DFF
做边界扫掠测得：

```text
1. 取 sky130_fd_sc_hd__dfxtp_1.spice（已有）
2. 配 sky130_fd_pr 的器件模型（nfet_01v8 / pfet_01v8_hvt）
3. 用 ngspice 跑瞬态：固定 clk，把 D 的到达时刻逐步逼近 setup/hold 边界
4. 记录 clk→Q 的延迟发散，拟合指数时间常数（得到 τ 的第三种、最可信的估法）
5. 发散起始窗口宽度即 T_w
```

**没有 T_w 的影响**：从上面的表可以看到，T_w 从 20 ps 变到 100 ps 只让 MTBF
变化不到一个数量级，而 τ 从 20 变到 60 ps 会变 10^49 倍。所以
**缺 T_w 不改变任何工程结论**，这也是本次可以接受"用文献 50 ps 代入"的原因。

## 七、若要换用别的 PDK

步骤与本次相同，只换数据源：

| PDK | 获取 | 特点 |
|---|---|---|
| SkyWater SKY130 | `skywater-pdk-libs-sky130_fd_sc_hd`（Apache-2.0） | 本次使用，开源可商用 |
| GF180MCU | `gf180mcu-pdk`（Apache-2.0） | 180 nm，含 MCU 器件 |
| IHP SG13G2 | `IHP-GmbH/IHP-Open-PDK` | 130 nm BiCMOS，教学常用 |
| 商业 PDK（TSMC/SMIC） | 通过 foundry 或 EDA 厂商，通常需 NDA | 有完整 .lib 与 SPICE 模型 |

接入代码只需改 `scripts/sky130_mtbf.py` 里两个路径：

```python
PDK   = r"...\<cell_dir>"          # 单元目录（含 .spice 与 .lib.json）
LIBJ  = os.path.join(PDK, "<cell>__<corner>.lib.json")
SPICE = os.path.join(PDK, "<cell>.spice")
```

工艺参数（`TOX_NM`、`MU_N`、`MU_P`、`VOV_TYP`、`CJ_FF_PER_UM`）按新 PDK 替换即可。
