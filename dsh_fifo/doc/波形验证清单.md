# 波形验证清单 — 看到什么才算对

本清单告诉你：**在 Wave 窗口里看哪些信号、它们的正确表现是什么、怎么量化**。
每条判据都可以当场核对，不需要相信我说的"通过了"。

---

## 0. 准备：加载信号并跑一次

在 ModelSim 的 Transcript 里：

```tcl
# ① 重新加载（+acc 保留内部信号，看得到 fifo 核里的东西）
vsim -voptargs=+acc work.tb_top +TEST=tc1 +SEED=1 +STAGES=2

# ② 加载本工程的波形观察配置（7 组信号，自动分组和格式）
do ../../scripts/wave_view_a.do

# ③ 运行
run -all
```

> **顺序不能反**：`add wave` 必须在 `run` 之前，否则没有历史数据（这就是你之前波形空白的原因）。

以上命令假定当前目录是 `sim/msim_2stage/`，并已运行过一次 `scripts/run_sim.cmd` 生成对应的库。

跑完后 Wave 窗口应该有 7 个分组共 32 个信号、时间轴约 `0 → 17.7 us`。

## 1. 时钟周期 —— 用光标量，验证 5:3 与 7:2

| 信号 | 期望周期 | 对应题面 |
|---|---|---|
| `wr_clk_a` | 10 ns | A 通道写 |
| `rd_clk_a` | 6 ns | A 通道读（5:3 中的 3） |
| `wr_clk_b` | 14 ns | B 通道写 |
| `rd_clk_b` | 4 ns | B 通道读（7:2 中的 2） |
| `clk_mon` | 5 ns | 监控域 |

**怎么量**：

1. 点 Wave 窗口底部的 **Cursor 1**，拖到一个 `wr_clk_a` 的上升沿
2. 点 **Cursor 2**，拖到**下一个**上升沿
3. 看底部表格 `Delta` 那一列

`Delta` 显示 `10 ns` 就对了。其余四个时钟同样操作。

> 这一步直接证明"非整数时钟比"是真的——10 : 6 不是整数倍，指针同步点每拍都在滑动。

---

## 2. 复位同步释放 —— 必须滞后 2 个时钟

| 信号 | 期望 |
|---|---|
| `/tb_top/h/rst_n_async` | 外部复位，宽带 |
| `.../u_rst_sync_wr/rst_n_sync` | **比 rst_n_async 晚 2 个 wr_clk 才拉高** |
| `.../u_rst_sync_rd/rst_n_sync` | **比 rst_n_async 晚 2 个 rd_clk 才拉高** |

**判据**：两个 `rst_n_sync` 的上升沿都不与 `rst_n_async` 的上升沿同时，
而是落后 2 个对应时钟周期（2 级同步器）。

这是"异步置位、同步释放"的直接证据——避免复位撤销时各触发器不同步。

---

## 3. 格雷码单比特跳变（**最关键**）

这是异步 FIFO 的核心，必须亲眼看到。

**看 `wr_gray`（binary 显示），它在每个 `wr_fire` 时变化：**

| `wr_bin`（十进制） | `wr_gray`（9 位二进制） |
|---|---|
| 0 | `000000000` |
| 1 | `000000001` |
| 2 | `000000011` |
| 3 | `000000010` |
| 4 | `000000110` |
| 5 | `000000111` |
| 6 | `000000101` |
| 7 | `000000100` |

**判据**：**任意相邻两个不同的 `wr_gray` 值，只有 1 位不同。**

这正是格雷码的定义，也是"跨时钟域只同步 1 bit 变化，避免多比特同时跳变被采到中间态"的原理。

**对比看**：同时显示 `wr_bin`（unsigned）。你会看到 `wr_bin` 从 `001111111`(127)
变到 `010000000`(128) 时**9 位全变**——如果直接同步这个，
采到中间态就会得到完全错误的值。这就是为什么必须先转格雷码。

---

## 4. 跨域同步 —— 滞后但不失真

| 信号 | 含义 | 期望 |
|---|---|---|
| `wr_gray` | 写域当前格雷码 | 实时变化 |
| `wr_gray_sync` | 读域看到的版本 | 与 `wr_gray` **形状相同，延迟 2 个 rd_clk** |
| `wr_bin_sync` | 解码后的二进制 | 等于 `wr_gray_sync` 对应的二进制值 |

**判据**：
- `wr_gray_sync` 的每次跳变都发生在 `rd_clk_a` 的上升沿（不是 `wr_clk_a`）
- `wr_gray_sync` 的值序列与 `wr_gray` 完全一致，只是时间上晚一点
- `wr_bin_sync` 是 `wr_gray_sync` 的格雷码解码结果，**中间不会出现毛刺或非法值**

把光标放在同一个 `wr_gray` 值上，`wr_gray_sync` 应在之后 2 个 `rd_clk` 出现相同值。

---

## 5. 空满标志与精确占用量

| 判据 | 怎么核对 |
|---|---|
| 复位后 `rd_empty=1`、`rd_occupancy_r=0` | 波形最左端（复位释放后） |
| 写入后 `rd_empty` 变 0 | `wr_event_cnt` 第一次从 0 变 1 之后 |
| `wr_full=1` 时 `wr_occupancy_r=256` | 找到 `wr_full` 第一次变 1 的位置 |
| `wr_full=1` 时 `wr_ready=0` | 同一位置看 `wr_ready`，必须是 0 |
| `rd_empty=1` 时 `rd_valid=0` | 找到 `rd_empty` 变 1 的位置 |
| 稳态时 `wr_occupancy_r ≈ rd_occupancy_r` | 二者都表示"FIFO 内字数"，收敛后应相等（差值只是同步延迟） |

**这条验证了一个关键设计点**：本设计用"精确占用量计数器"而不是"格雷码指针比较"，
所以 `wr_full` 恰好在 `wr_occupancy_r = 256` 时置位，**FIFO 能真正存满 256 字**
（经典的指针比较方案只能存 255 字）。

---

## 6. 握手保护 —— 满时不写、空时不读

| 场景 | 期望表现 |
|---|---|
| `wr_full=1` 且 `wr_valid=1` | `wr_fire=0`（写入被拒）、`wr_bin` **保持不变**、`ovf_try=1`（记录一次满时尝试） |
| `rd_empty=1` 且 `rd_en=1` | `rd_pop=0`（弹出被拒）、`rd_bin` **保持不变**、`unf_try=1` |
| 正常写入 | `wr_valid=1` 且 `wr_ready=1` 时，`wr_fire=1`，`wr_bin` 在**下一个**时钟沿 +1 |

**判据**：`wr_fire = wr_valid & wr_ready`，`rd_pop = rd_en & rd_ready & rd_valid`。
用波形验证这个组合关系始终成立。

---

## 7. 阈值与回差（almost_full / almost_empty）

**默认阈值**：`almost_full` 在占用量 **224** 置位、**222** 清除；
`almost_empty` 在 **32** 置位、**34** 清除（回差 2 字 = `DEADBAND`）。

**怎么核对**：

1. 找到 `wr_almost_full` 第一次变 1 的位置
2. 看同一时刻的 `wr_occupancy_r` 值 → 应该是 **224**
3. 再往右找它变回 0 的位置
4. 看那时的 `wr_occupancy_r` → 应该是 **222**

**判据**：置位点和清除点相差 **2**，这就是"回差/去抖动"——阈值附近不会来回抖动。

> 用 `tc4` 跑这个最清楚（它就是专门测阈值的），
> 日志里会打印 `[TC4] A almost_full rise point = 224` 这样的实测值，可以和波形对照。

## 8. 背压（用 tc5 看）

```tcl
vsim -voptargs=+acc work.tb_top +TEST=tc5 +SEED=1 +STAGES=2
do wave_view_a.do
run -all
```

| 信号 | 期望 |
|---|---|
| `rd_ready_a` | 会被随机拉低（这不正常！是测试故意制造的"下游没准备好"） |
| `rd_valid_a` | 此时仍为 1（FIFO 里有数据） |
| `bp_cyc` | 与 `rd_valid & ~rd_ready` 同时为 1 |
| `rd_pop` | **为 0**（数据没被取走） |
| `rd_bin` | **保持不变** |
| `rd_data` | **保持不变**（输出保持住，下游随时可取） |

**判据**：`rd_ready=0` 期间读指针不推进、输出数据不丢，`rd_ready` 恢复后数据仍正确。

---

## 9. 数据通路完整性

| 信号 | 期望 |
|---|---|
| `wr_data_a` | 写入的数据（不同模式下不同：随机、全0、全1、交替） |
| `wr_addr` | `= wr_bin` 的低 8 位 |
| `rd_addr` | `= rd_bin` 的低 8 位 |
| `rd_data` | `= mem[rd_addr]`，组合读出，**与 `wr_data_a` 的写入顺序一致** |

**判据**：随便挑一段，`wr_data_a` 写进去的值，应该在延迟一段时间后从 `rd_data` 按**同样顺序**出来。

> 严格比对由 TB 的参考序列完成（`sent_a[]` 逐项对比），波形只是直观确认。

## 10. 用光标量化的通用方法

| 操作 | 方法 |
|---|---|
| 移动光标 | 点 Wave 窗口底部 `Cursor 1` / `Cursor 2` 行，再在波形区点击目标时刻 |
| 读 Delta | Wave 底部表格有 `Now`、`Cursor 1`、`Cursor 2` 和差值列 |
| 精确定位边沿 | 用工具栏的 **Find Next Transition**（跳转到下一个跳变沿） |
| 缩放到某区间 | 按住鼠标拖选波形区域，或 `wave zoom range 100 200` |
| 看全部 | `wave zoom full` |
| 改显示格式 | 信号名上右键 → `Radix` → Binary / Unsigned / Hexadecimal |

## 11. 不同用例看什么

| 用例 | 重点观察 |
|---|---|
| `tc1` | 写满 256 → `wr_full`；读空 → `rd_empty`；格雷码序列 |
| `tc2` | 读写交替时 `wr_occupancy_r` 的连续变化；5000+ 次混合操作 |
| `tc3` | `wr_full=1` 时 `wr_valid` 仍为 1，看 `ovf_try`/`overflow_cnt` 递增而 `wr_bin` 不动 |

## 12. 波形验证的定位（重要）

波形能证明的是"**这些信号在时间上的行为符合预期**"，适合：

- 直观确认设计意图（答辩讲解）
- 观察断言难以表达的时序关系（如格雷码单比特跳变）
- 定位失败时的现场（`[FAIL]` 报告的时间戳可以直接跳过去看）

但它**不是主要判据**。正式判定靠：

| 层次 | 手段 | 规模 |
|---|---|---|
| 自检断言 | `ck()` 检查点，逐条打印时间戳 | 每用例 700~5500 条 |
| 参考模型 | `sent_a[]` 序列逐项比对 `rd_data` | 覆盖所有读写 |
| 功能覆盖率 | 29 个 bin（7 类覆盖点） | 需达 100% |
| **变异测试** | 注入 3 个 bug 看是否被抓 | 3/3 必须捕获 |

所以完整结论是：**波形 + 日志 + 覆盖率 + 变异测试** 四者一致，才算验证通过。

## 13. 快速自检（30 秒版）

如果只想确认"设计是活的"，看这 4 条：

1. `wr_clk_a` 是方波，周期 10 ns
2. `wr_bin` 从 0 递增到 256，然后 `wr_full` 拉高
3. `wr_full` 拉高时 `wr_ready` 立刻变 0
4. `wr_gray` 每次只变 1 位

四条都对，基本可以确认 FIFO 的核心机制正常。其余细节按第 5~9 节逐项核对。
